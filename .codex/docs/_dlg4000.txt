Características Gerais do Produto

O datalogger é um equipamento com o objetivo principal de digitalizar sinais elétricos
analógicos com uma entrada de sensores tipo universal e gravar esta informação em um
cartão do tipo SDHC, podendo o produto funcionar sem a necessidade de um operador ou
um notebook.

O produto tem uma dimensão e consumo de energia reduzidos, para que seja possível
sua aplicação em locais de difícil acesso e/ou testes de longa duração.

Para utilizá-lo, recomenda-se primeiro configurar o(s) sensor(es) conectado(s) no(s)
canal(is) analógico(s), para que se possa obter o melhor sinal possível, isto é, a maior
resolução sem distorção do sinal. Depois disso, configura-se o modo de aquisição e
gravação e pronto, é só iniciar o ensaio.


Características Gerais das Entradas e Saídas de Sinal

   •   É possível configurar todo o sistema (tipo de entrada, ganho, balanço, etc) sem
       precisar abrir o equipamento;
   •   Sensores: ponte completa, ¼ de ponte (120 ou 350), ½ ponte, termopar, corrente,
       tensão (AC/DC +- 10V), ICP;
   •   Tensão de excitação de 0 a 5V configurável por canal, com possibilidade de uma
       outra versão de hardware com tensão de 0 a 10V (maior consumo);
   •   Alimentação de ±12V para sensores;
   •   Shunt-cal: global ou por canal (interno);
   •   8 canais analógicos;
   •   Filtro analógico anti-aliasing tipo Butterworth fixo em 2048 Hz;
   •   Frequência de aquisição fixa em 12,5 KS/s;
   •   Decimação e filtro passa-baixa digital programados por software;
   •   Ganhos ajustados de fábrica e selecionáveis por software
       (1,3,10,30,100,300,1000,3000);
   •   Ganho de usuário programado por software;
   •   Balanço de ±20mV e offset de ±10V, os dois com 16bits de resolução e
       selecionáveis por software;
   •   Impedância de entrada para tensão contínua : 100KΩ ou flutuante, selecionável
       por software;
   •   4 entradas de contadores normais ou 2 duas de contadores tipo quadratura;
   •   Sensor de 3 eixos de aceleração interno;

Detalhamento p/ Auto-zero

        Para realizar o auto-zero do canal, deve-se atuar no D/A de balanço/offset,
utilizando o algoritmo de busca binária, tendo-se como mínimo passo 20mV/216 (caso
balanço) ou 20/216 (caso offset).


Detalhamento p/ Calibração com shunt-cal

       1. obter valor X1 em engenharia do canal a ser calibrado
       2. aplicar shunt cal
       3. obter valor X2 em engenharia do canal a ser calibrado
       4. realizar contas (??) utilizando o valor da variável Canal[n].ValorShunt e colocar
       valores resultantes na configuração do canal.

      Detalhamento para Calibração do canal

       Cada ganho de cada canal deve ter uma equação linear associada, que será
aplicada aos dados brutos. Para calibrar o aparelho:

          1. coloque o maior filtro possível para não afetar as medidas
          2. aplique o ganho no canal que se deseja calibrar, com o balanço zerado e
              desligado.
          3. limpe os dados anteriores de configuração: coloque “0” em Offset_DA, “0”
              em offset_B e “1” em Gain_M.
          4. aplique N+1 tensões na entrada, começando-se por 0 até 10V. Levante a
              equação da reta y=A*x + B, onde y é o valor real medido, x é o valor ideal e
              B é o valor de offset em níveis do A/D. Lembre-se que A e B são float32.
          5. envie para a FW o valor de m=g/A, onde g é o ganho atual, junto com o
              valor de B, que será o offset_B.
          6. na FW, faça as seguintes contas:
          7. x= (y-b) * m
          8. GAIN_M = (int32_t) (m * (1<<15));
          9. offset_B = (int32_t) (B * (1<<15));
          10. offset_bm = ((int32_t)(1<<15)*(0,5) – (GAIN_M * offset_B);
          11. para cada amostra:
          12. valor_32 = ((int32_t)valor_medido_16) * GAIN_M)
          13. valor_32 = valor_32 + offset_bm
          14. valor_final = saturate ( valor_32>>15 ) ;

      Detalhamento dos circuitos eletrônicos
       O circuito eletrônico da placa de canal é baseado e compatível com o projeto ADS
5000 (H6389) onde sua principal característica é a modularidade dos canais.
       O circuito da placa mãe é simples e de baixo consumo, além de ser baseado e
fimware-compatível com o projeto DLG021 (H6979). Ficou decidido colocar um FPGA
para implementar a decimação digital.
       Maior detalhamento pode ser obtido nos esquemas elétricos do projeto.


       Detalhamento da mecânica

       A mecânica do projeto teve como príncipio a praticidade de utilizar uma caixa
pronta disponível no mercado. A marca BOPLA com o seu perfil ALUBOS foi a que
atendeu melhor os requisitos de dureza e praticidade.
       O tamanho e o perfil selecionados foram resultados da escolha por 8 canais no
sistema, na decisão de ser o menor possível e na exigência de se utilizar o circuito de
canal analógico do sistema ADS5000.
       Ao mudar o conector placa-placa dos canais analógicos para SMD obteve-se um
enorme ganho

        Neste tópico são listadas as estruturas de dados comuns a algumas mensagens do
        protocolo de comunicação.

        CUIDADO: Nos módulos do programa em que as estruturas de dados forem declaradas deve ser
        utilizada a diretiva do compilador para definir alinhamento byte da estrutura. Isso evita que o
        compilador inclua bytes dummies na estrutura de dados para otimizar o acesso à memória. O
        mesmo cuidado deve ser tomado na declaração das estruturas das mensagens. Do contrário as
        mensagens enviadas ficariam erradas.

        CUIDADO: Esta especificação assume que a ordem de armazenamento dos bytes na memória é
        o little endian. Essa é a ordem utilizada pela Intel nos seus processadores para PC.

Observações:            Os campos DisBlockIP, OwnerIP e sTag são os mesmos das mensagens
                        pcDLGSetSecureIP e pcDLGGetSecureIPR.

                        O campo sModel é uma string terminada em zero com até 16 caracteres
                        utilizados para a identificação do modelo do equipamento.
                        A versão do hardware e do firmware do equipamento são codificados nos
                        campos VersionP1 e VersionP2 conforme descritos nos comentários da
                        estrutura de dados.

                        O tipo TpRealLynx é um inteiro de 16 bits sem sinal utilizado para
                        representar um número real em formato compactado. Esse formato é
                        utilizado para representar as opções de freqüência de corte dos filtros,
                        opções de ganho e de tensão de excitação. Os três nibbles menos
                        significativos definem a mantissa e o nibble mais significativo a potência de
                        10. O bit mais significativo do nibble da potência índica o sinal da potência.
                        Exemplos: o valor compactado 0x9005 representa o valor real 0.5 e o valor
                        compactado 0x3002 representa o valor real 2000.

                        O campo CondGain é uma lista com as opções de ganho dos
                        condicionadores de sinais do DLG. Os valores nominais dos ganhos são
                        representados no formato TpRealLynx. A lista pode ter até 16 opções de
                        ganho. Caso o número de opções de ganho seja menor que 16, após a
                        última opção deve ser armazenado o valor binário 65535.

                        Analogamente os campos ListLPF e SensPwr apresentam respecticamente
                        as opções de freqüência de corte do filtro passa baixas e as opções de
                        tensão de excitação dos sensores.

                        O DLG possui 5 tensões de excitação : 1V, 2,5V, 3,3V, 5V, user e dois filtros
                        digitais passa-baixas: 1/10 e 1/3 de Fa/2.

                        O DLG não possui filtros passa altas, com isso o campo ListHPF deve
                        ser preenchido com o valor binário 65535.

                        O DLG também não possui suporte para filtros notch, com isso o campo
                        Notch deve ser igual a zero.

                        Os campos sTechnician, sAdjustDat e dtAdjust2K devem ser ignorados pelo
                        DLG. Eles são passados para o DLG na mensagem
                        pcDLGSaveAdjust.

Programa o Ajuste de Escala de Ganho de um Canal
(pcDLGSetChGnAdjust)
Propósito:              Esta mensagem é utilizada para passar o ajuste de uma escala de ganho de
                        um canal.
                        A escala de ganho deve ser ajustada de modo que o ganho entre a saída do
                        canal (em +/- 10V) e a entrada do condicionador tenha o menor erro em
                        relação ao ganho nominal.

Formato da Mensagem:    TpPcDLGSetChGnAdjust

Packet Code:            pcDLGSetChGnAdjust

Formato da Resposta:    TpPcDLGGenericResp

Packet Code:            pcDLGSetChGnAdjustR

Observações:            O campo Channel corresponde ao canal a ser ajustado (0 a 8).

                        O campo iGain corresponde ao índice da escala de ganho a ser ajustada (0 a
                        nGain-1). O valor de nGain corresponde ao número de escalas de ganhos do
                        equipamento. O padrão de fábrica deve ter os seguintes ganhos: 1,
                        3,10,30,100,300,1000,3000.
                        O ajuste da escala de ganho é determinado pelos campos Offset_DA,
                        Offset_B, Gain_M.

                        O ajuste analógico do offset é dado pelo campo Offset_DA (-32768 a 32767).
                        Esse controle é aplicado no circuito de entrada.
                        O ajuste digital do offset é dado pelo campo Offset_B (-32768,0 a 32767,0).

                        O campo Gain_M corresponde ao ganho digital necessário para se obter o
                        ganho pretendido.

       uint16_t           Channel;            // Número do canal
       uint16_t           iGain;              // Índice do ganho (0..nGain-1)
       int16_t            Offset_DA;   // Ajuste de offset do primeiro estágio –

Mensagem de Comando para o Coletor de Dados
(pcDLGCommandDLog)

Propósito:              A aplicação do microcomputador utiliza esta mensagem para programar a
                        aquisição de sinais do coletor de dados.


Formato da Mensagem:    TpPcDLGSetProgDLog

Packet Code:            pcDLGGetGPS_Setup

Formato da Resposta:    TpPcDLGCommanDLogR

Packet Code:            pcDLGSetProgDLogR
Observações:
                        O campo Command define o comando a ser executado pelo coletor de
                        dados:

                        0: Get Status
                        Informa o status da operação do coletor de dados.

                        1: Start
                        Inicia a operação do coletor de dados conforme a programação
                        previamente enviada. Se o DLG estiver com a aquisição de sinais
                        em tempo real ativa (veja as mensagens pcAcqSetup e pcAcqStart) e a
                        freqüência de amostragem configurada para operação no modo coletor de
                        dados for diferente da aquisição em tempo real, o comando Start deve ser
                        rejeitado (código de erro diferente de zero).

                        2: Stop
                        Finaliza a operação do coletor de dados. A coleta que eventualmente
                        esteja em andamento deve ser finaliza e o arquivo fechado.
